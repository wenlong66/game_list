# 开源游戏库：AI 换皮、持续开发与投入选型

基于现有游戏保留主要玩法，替换游戏名、品牌、界面、美术和其他外部内容，制作自己的独立版本；优先选择能由 AI 编程完成资源接入、工程修改，并继续迭代玩法的项目。同时考虑首次成品的时间、现金支出、维护和运营成本，而不是只看技术上能否实现。

分类更新：**2026-10-13**，已加入成本与时间判断。原始收藏清单日期：2026-07-01。

> 平台硬条件：**支持 Windows，或同时支持 iOS + Android**。仅 Android 不满足。这里的 AI 指开发阶段的编程 Agent，不要求游戏运行时接入大模型。
>
> 当前分类是基于仓库说明、工程配置、许可证和官方文档的选型判断，**所有项目均未在本次实际构建、换皮或运行验收**。平台声明、已有构建工程与实测通过是三个不同状态；许可证摘要不替代完整的代码、素材和分发审计。成本等级与工时范围均为低置信度规划估算，不是报价或交付保证。

## 成本与时间：新增判断依据

把 **一次性现金、本人/团队工时、持续维护/运营、渠道及合规费用** 分开。开源免费不代表开发零成本，已有 AI 订阅不代表人工验收、素材返工和额度占用为零。先通过平台、授权和独立工程检查，再比较投入；低成本不能抵消硬条件。

以下仅是**可选的 S1 受控范围独立首版**估算：单人 + AI，Windows 单端，每人日 6 小时，保留主要规则和二维表现、采用小内容集与少帧方案，包含素材制作/接入、常规返工和基本回归；累计工时已包含 S0 样例验证。不是全量原版内容换皮，也不是纯编码时间或日历天。

## 分类标准

同时比较 **AI 换皮接入难度、首次成品时间、现金成本与后续维护/运营成本**；检查平台路线、玩法完整度、资源依赖和授权限制。不仅按语言、项目大小、Star 数或“支持 Mod”判断。原 A/B/C/D/P 保留为适配分类，**A 类不等于成本最低、时间最短**，同类项目按目标范围和试做结果复排。

- **A｜优先验证**：资源与规则入口清楚，适合先做独立换皮版本。
- **B｜有条件推荐**：能用，但要限制项目规模、动画复杂度或接受补玩法。
- **C｜低优先级**：不是不能改，而是整套资源替换、独立化或回归成本偏高。
- **D｜独立发行前置条件未解决**：授权限制或工程不完整，不能默认作为自由发行底座；不代表所有个人、非商业或已授权用途都不可用。
- **P｜平台待补**：当前收藏仓库尚未确认满足平台硬条件。

## 换皮与发行的共通边界

**换皮是产品选择，不会自动消除代码许可义务。**保留应保留的许可证、版权声明和署名；源码许可与素材许可分开核验。GPL 不等于禁止收费，MPL 不等于整套代码可闭源，MIT 代码也不代表第三方素材可随意使用。

**平台工程存在不等于当前可构建，更不等于商店审核通过。**iOS 签名、工具链、许可证与具体分发方式，以及 App Store 的 Copycats / Spam 规则都需要独立检查。

**编程接入不等于美术生产。**AI 可承担资源清单、切图、打包、引用映射、界面与代码修改；一致的美术、动画、音频需要授权素材或生成工具供给，并做视觉验收。

## 开工前验收

先固定版本并构建原版，再完成一个可玩闭环的完整换皮；验证资源无错误回退、碰撞与动画正常、独立包名和存档空间正确、目标设备能够运行。随后再增加玩法。内部玩法 ID 不做无理由的全局替换，避免破坏引用和存档。

试做同时记录资源数量、通过率、有效人工工时和实际生成/模型支出，再按[成本与时间方法](docs/cost-and-time-assessment.md)估算全量；未确认范围时不把样例成本外推为整款成本。

具体清单与授权来源见[详细分析](docs/ai-game-dev-recommendations.md)。上述验收尚未执行，不以“文档已分类”代表“游戏已验证可发行”。
