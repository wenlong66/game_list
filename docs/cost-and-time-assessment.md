# 成本与时间：AI 换皮项目的投入评估

更新日期：2026-10-13。返回[分类首页](../README.md)或[逐项技术分析](ai-game-dev-recommendations.md)。

> 本文增加成本、时间与维护负担，不替代原有平台、授权及 AI 开发条件。所有金额模型、相对等级和人日范围都是初步规划方法或工程估算，不是报价、实测工期或交付保证。尚未盘点全量资源、构建游戏、测试 AI 美术产能；当前估算置信度低。

## 1. 判断顺序

先过硬条件，再比较投入：**Windows，或 iOS + Android**；所选使用/分发方式有可行的授权路径；能够做独立版本。授权或完整工程缺失不能被“便宜、快”抵消。用户没有要求闭源，也没有将收费作为唯一用途，不因此一概排除 GPL 或所有非商业用途。

通过前置检查的项目，再同时比较：AI 换皮接入难度、首次成品所需时间、现金支出、长期维护/运营。没有预算上限、目标内容量和实际吞吐前，不用精确加权分数制造客观排名。原 A/B/C/D/P 是适配分类，**A 类不等于最便宜或最快**。

## 2. 范围先于估算

| 阶段 | 完成标准 | 不能冒充什么 |
| --- | --- | --- |
| S0：代表性样例验证 | 原版可构建；一个代表性对象、场景和界面资源完成替换，验证导入、打包、碰撞/动画与运行 | 不等于整款游戏换皮完成，也不等于完整独立包 |
| S1：受控范围的独立首版 | 明确限定的内容集可完成一局/关卡/核心循环；该范围内所有可达外观资源、品牌、UI、音频与包装已替换或采用经确认可保留的授权内容；独立包名、存档和更新配置正常 | 不是保留原版全部内容的成品。未覆盖内容必须明确隔离且验证不可误加载，不能靠旧资源回退假装完成 |
| S2：保留原版内容规模的完整换皮 | 所有纳入范围的单位、装备、地形、关卡、界面、动画状态、文案、音频及必要隐藏资源路径都完成替换与回归 | 不可用 S0/S1 的低投入来报价；开源署名和许可证不应被当成需要清除的旧品牌 |

用户的完整目标不能自动降为 S1。S1 只是用于比较投资规模的可选方案，是否缩小内容需另行决定；本次没有修改任何游戏的内容范围。**S2 在全量盘点前只给相对成本/工期等级，不填虚假的确定周数。**

## 3. 初步时间表的共同假设

下表数值仅适用于 S0/S1：一名开发者配合编程 Agent 和可用的美术生成/授权素材工具，每人日按 6 小时有效项目投入计算；以 Windows 单端为基准，已有开发电脑。保留主要规则、二维表现、同类题材与近似的资源尺寸/动作结构，不同时重写引擎、联网或增加支付/账号系统。

S1 假设是小规模内容集、一个主题、少帧或静态表现，包含设计、素材筛选与接入、常规返工、独立打包和基本回归；不是纯编码时间。非商业原型和成熟游戏成品分开比较。外包排队、授权谈判、商店审核、重大工具链迁移、高清全动画与全量原创剧情不在这些数值内；发现这些需求时必须追加工作项，而不是强行沿用范围。

**S0 与 S1 均从开工累计，不能相加。**人日不是 AI 运行日，也不等于日历天；单人每周投入 30 小时时，日历工作周约为人日 / 5。兼职按实际可投入小时折算，AI 并发不代表人工验收能同比并发。

## 4. 各项目的投入判断

相对等级描述同等美术质量、保留主要玩法时的预计整体工作负担，不是已经清点的资源数量，也不对应固定人民币区间。S1 范围必须逐项目确认，表内范围有重叠，不能据此断言第二名一定比第三名快。

| 项目 | S0 样例验证（人日） | S1 小范围 Windows 独立首版（累计人日） | S1 直接现金压力 | S2 完整换皮成本 / 工期压力 | 后续维护压力 | 主要成本驱动 |
| --- | --- | --- | --- | --- | --- | --- |
| Unciv | 3–7 | 15–35 | 低–中 | 中 / 中 | 低–中 | 图标、地形、规则引用及未被 UI skin 覆盖的界面；不能漏算时代、单位和地形组合 |
| Mindustry | 4–10 | 25–55 | 中 | 中–高 / 高 | 中 | 建筑、单位部件、特效、地形和图集；新增平台需要单独回归 |
| Endless Sky | 4–10 | 20–45 | 中 | 高 / 高 | 中 | 舰船挂点与碰撞、装备/界面，以及保留原版内容规模时的大量任务、文案和素材 |
| Microverse | 2–5（Demo） | 暂不估成熟成品 | Demo 低–中 | 未定：需先定义玩法成品 | 中–高 | 换一个小场景不等于补完成熟玩法；保留云端大模型功能时有持续调用与故障处理开支 |
| OpenRA | 5–15 | 35–80（限小阵营与少帧方案） | 中–高 | 高 / 高 | 中–高 | 多方向单位、建造/损坏状态、地形拼接和独立资源集；同等丰富动画不能套用少帧估算 |
| Wesnoth | 5–12 | 25–60（限小战役与棋子化方案） | 中 | 高 / 高 | 中 | 战役、立绘与单位动画；全量内容和原版级动画另估 |

| OpenTTD | 5–15（仅代表性资源） | 暂不估 | 中–高或未定 | 高 / 高 | 中–高 | 自由基础资源、NewGRF、道路/轨道与方向组合；单套车辆换图不等于整款完成 |
| OpenRCT2 | 先验证无原版文件的资源闭环 | 暂不估 | 未定 | 很高 / 未定 | 高 | 原版资源依赖、设施状态、动画与加载链；缺少可独立运行验证时不能报成品期限 |
| OpenXcom | 先验证资源替代与构建 | 暂不估 | 未定 | 高 / 未定 | 高 | 原版数据、旧格式和完整独立化；不能只算战术画面换图 |
| jynew | 先明确使用/分发授权 | 暂不估 | 授权及依赖成本未定 | 未定 / 未定 | 待授权后评估 | 自定义代码/素材许可及第三方插件，不能默认授权费为零 |
| DevilutionX | 先明确使用/分发授权 | 暂不估 | 授权及资源成本未定 | 未定 / 未定 | 待授权后评估 | 收藏版许可和原版数据限制，不能当自由收费发行底座来报价 |
| Shattered Pixel Dungeon（额外候选） | 3–7 | 15–35 | 低–中 | 中 / 中 | 低–中 | 有自有版本修改指南；仍有装备、动画帧、界面及图集一致性工作；iOS 不在 Windows 估算内 |

上述数值是同一假设下的排期占位，不是源文档提供的工期。所有项目的 S2 确切人日、现金报价和实际每月维护工时均为**待测/待报价**；没有因为添加了表格就成为已验证的低成本项目。

## 5. 成本必须分账

| 费用项 | 应记录内容 | 计费边界 |
| --- | --- | --- |
| 一次性直接现金 | 新增或升级的 AI 编程用量、图像/音频生成、素材/字体/音乐授权、必要插件、外包、临时构建资源、增量测试设备 | 已有订阅的新增现金可为零，但项目占用额度与分摊成本不是零；不要重复计算包内额度和同一笔 API 费用 |
| 开发时间成本 | 配环境、梳理资源、提示/生成返工、人工挑选和修图、接入、测试、文档、发布准备 | 自己做没有工资转账，也仍然有机会成本；外包费已计现金时，不再把同一份外包劳动重复计成人日成本 |
| 持续维护/运营 | 模型或服务账单、后端/存储/带宽、Bug 回归、系统/商店 SDK 升级、存档迁移、上游安全与兼容更新 | 开发阶段使用 AI 不等于玩家运行时必须付 AI 费用；保留联网、云服务或运行时大模型时另算 |
| 渠道及合规 | 开发者账号、产品提交费用、证书/签名服务（如需要）、授权/合规审查 | 按选择的商店和地区查官方当期规则；账号级费用不要逐游戏全额重复算，税费和审核等待另记 |

建议同时保留两个总数：

```text
新增现金预算 = 实际新增的一次性支出 + 预计持有周期内新增的运营账单
完整经济成本 = 归属于项目的现金支出（含必要分摊）
             + 未计入现金的本人/团队有效工时 × 自定小时价值
             + 明列的风险预留
```

比较项目时统一维护周期，例如都看首版之后 6 个月，不能用一个项目的一次性开支与另一个项目的一年运营费比较。维护比较同时记录“每次相同规模更新”的工时；不能拿一个只修 Bug 的项目与一个每周加内容的项目对比。

本次没有指定模型/素材供应商，也没有实际出图、返工和用量数据，因此**不填一个看似精确的人民币总价**。低/中/高是相对压力，正式金额要用实际供应商单价、试做吞吐和可用额度计算，不能将开源免费推导为开发零成本。

## 6. 怎样把估算变成可用预算

先做固定范围的试做，记录各类型资源的有效耗时与支出，而不是只记录“AI 生成用了几分钟”。

```text
第 k 类资源预计人日
  = 该类尚需验收通过的数量 × 样本中每件通过资源的平均总人工小时 / 6
  （总人工小时包含筛选、失败尝试分摊、修图、接入与验收）

完整项目预计人日
  = 工具链与资产管线 + 各类资源预计人日之和
  + 必要代码/界面修改 + 独立打包 + 全量回归 + 明列风险工作项
```

不把一张静态图的速度直接外推到动画、地形拼接和多方向角色。将“创作次数”“通过验收数量”和“现金用量”分别记录：失败生成也可能收费；图能显示不代表风格、碰撞或授权合格。

每次记录：仓库固定提交、目标平台、S0/S1/S2、保留内容清单、资源分类数量、样例通过率、每类有效人工小时、AI/生成账单、依赖/授权缺口、乐观/正常/悲观情景与更新时间。出现构建失败、频繁旧图回退、低素材通过率、原版依赖未解或需要重写底层时，先重新估算，不继续承诺原工期。并行任务按关键路径计算日历时间，等待时长和劳动工时分别记录。

## 7. 平台与运行时费用不能漏算

Windows 时间表不代表三端工期。以已有桌面工程为起点，Android/iOS 的触控、适配、性能、签名、真机、存档和发布回归均另列工作包；已有平台工程只能降低起步不确定性，不能把新增工时记为零。本次不凭空套一个通用的百分比或固定加几天。

只选择不新增自有云服务的单机路线，可能没有按玩家数增长的自有服务器账单，但仍有维护与分发成本。保留多人服务、自动更新、账户或遥测时，应实际盘点，而不是默认全部离线。

Microverse 若保留云端大模型 NPC：

```text
运行时模型费 ≈ 计费周期内全部实际调用的输入 token 费用
             + 输出 token 费用 + 其他计费项
             （包含记忆/摘要/规划调用、失败重试与必要后台调用）
```

再按供应商的缓存、阶梯及其他规则修正，并另算后端等账单。自带密钥是费用承担方式变化，不是系统无成本；本地模型也有算力、能耗和部署维护成本。没有玩家数、NPC 数、调用频次、上下文长度和供应商单价前，不承诺每月运营金额。

## 8. 加入成本/时间后的决策

| 场景 | 当前建议 | 不确定性 |
| --- | --- | --- |
| 现有收藏，Windows 先验证，控制首版投入 | Unciv 优先；Mindustry 与 Endless Sky 按题材、内容范围和资产试做结果复排 | 暂不维持无条件的第二、第三名；三者的技术适配优势不等于同样工期 |
| 允许新增，小型 Roguelike | 将 Shattered Pixel Dungeon 与 Unciv 放在首轮低投入验证组 | 是两个不同类型，不是量化证明两者总价相同；也不能称 Shattered 已被全量盘点 |
| 现有收藏希望三端都有工程基础 | Mindustry 优先做三端构建验证 | 三端路线优势不等于比单端项目便宜；报价必须包含三个平台 |
| 只需要很小的 Godot 沙盒 Demo | Microverse 可以先试 | 不把 Demo 的低成本排在成熟成品前，运行时 AI 成本另计 |
| 全量原版内容 + 高质量新动画/美术 | 先做全量盘点和代表性资源试做，再选项目 | S1 人日全部失效，不能宣传“几周完成整款换皮” |

按用户要求移除指定条目后，当前清单为 12 个游戏；Shattered Pixel Dungeon 仍单列补充候选，不计入这 12 个游戏。成本判断用于进一步排序和控制范围，不为低价项目跳过平台、授权和完整性检查。本次只同步清单与文档，没有实际开工、采购、创建 fork 或改变游戏内容范围。
